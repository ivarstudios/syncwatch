## (a) Scan now and the time of the last structure scan

**Before.** The structure scan runs every `structure_interval` (default 1 hour). A finding for a corrected mistake stayed
open until the next scan. No finding showed when syncwatch last checked. Only a restart of syncwatch started a new scan
immediately. On realsim, 6 corrected findings of the data steward stayed open for 28 to 33 minutes.

**Changed.**

- `internal/collector/structure.go`:
  - `startScan` starts each structure scan: the timed scan (`maybeScan`) and "Scan now" (`ScanNow`). It makes a
    baseline scan when one is due, else a regular scan. The timed scans count from its start.
  - `ScanNow` gives a `ScanStart` with 1 of 4 states. `started`: a new scan. `running`: a scan runs, and syncwatch
    starts no second scan. The answer then has the scan that runs. `too-soon`: an administrator started a scan of the
    server less than 30 seconds before (`manualEvery`). The answer then has the start of the last scan and the time
    of the next permitted scan. `not-up`: the server is not up, its first full check is not complete, or no session
    runs.
  - The channel `Done` closes at the end of the scan. Then `End` tells how the scan ended: complete, or stopped before
    the end (repair 3). A stopped scan does not count for the timed scans and for the 30 seconds.
  - `LastStructureScan` is now the end of the last scan that listed a share of the server, or that found no share
    (repair 1). Before, it was the start, and no code read it. Each share has `ListedAt`, the end of its last listing.
- `internal/collector/manager.go`: `Manager.ScanNow(serverID)`. A server without a collector that runs is `not-up`.
- `internal/collector/collector.go`: the fields `scanDone`, `sessCtx` and `manualAt`. `pollWait` reads `lastScan` under
  `scanMu` (commit 0bded17), because `ScanNow` sets it from a request of the dashboard.
- Commit 53c9ff9 is a repair that "Scan now" needs: each session starts its own `scanTimer`. Before, the timer ran with
  the first session only. After a reconnect in events mode, a due scan waited for the end of the long-poll (up to
  `event_timeout`). `ScanNow` starts its scan with the context of the current session (`sessCtx`).
- `internal/engine/engine.go`: `Engine.Settle(ctx, d)` asks for an evaluation. It waits until an evaluation that
  started after the call is complete. A `Trigger` also ends the wait of 1 second that collects the changes of the hub.
- `internal/web/scan.go` (new): `POST /structure/scan` (`handleScanNow`).
  - With `server`, it scans the server of a finding. Without `server`, it scans each enabled server (Settings →
    Structure).
  - A server that is not in the settings, or that is disabled, gets a red message and no scan.
  - The answer waits at most 5 seconds (`scanWait`) for the scans and for `Settle`. Then it redirects to `back`, with
    a message for each server.
  - An INFO log line records each scan that an administrator starts:
    `msg="administrator started a structure scan" server=AKKA role=admin login=password ip=192.168.1.33`. In proxy
    mode, the value of `login` is `proxy`.
- `internal/web/server.go`:
  - The route uses `s.action(RoleAdmin, …)`: the session, the CSRF token of the session and the Origin check. These
    are the rules of the other forms of the administrator.
  - The new function `Hooks.ScanNow`.
  - `setFlash`: an answer can have a green and a red message.
- `internal/web/views.go`, `templates/problems.html`:
  - Each structure finding (S1 to S7) has `Scan` and `ScanServer`. For S3 to S7, `Scan` is the end of the last scan
    that listed the share of the finding. For S1 and S2, it is the end of the last scan of the server (repair 1).
  - The line of the finding ends with `· last scan 09:05 (3 minutes ago)`.
  - The details have the row **Last scan**. Before the first scan, the row shows `no scan after the start of
    syncwatch`. While syncwatch cannot list the share, the row adds `syncwatch cannot list the share: timeout`.
  - The Overview tile of the server shows the same time: `Shares 2 · last scan 09:05` (repair 4).
  - Only an administrator sees the button **Scan now** in the details. The hint is "syncwatch scans the shares of AKKA

**DECISION w056-1: the scan of "Scan now" is the timed scan.** `ScanNow` calls `startScan`, the code of the timed scan.
When a baseline scan is due, "Scan now" makes the baseline scan. The timed scans count from its start. Thus no timed
scan follows some seconds later.

**DECISION w056-2: a press while a scan runs gets that scan.** syncwatch starts no second scan of a server and keeps no
queue. The answer waits for the scan that runs and shows its result. A timed scan can list the share before the
correction. Then its result does not show the correction, and a second press starts a new scan. The 30 seconds count
only the scans that an administrator started. On the real ORION data, a structure scan takes at most 0.1 seconds. Thus
this case is rare.

**DECISION w056-3: 30 seconds for each server, for all administrators.** The limit is in the collector of the server
(`manualEvery`). Settings → Structure gives each server its own line. A server in the 30 seconds gets the red message,
and the other servers scan.

**DECISION w056-4: the answer waits at most 5 seconds.** Thus the page after the answer shows the result of a normal
scan. In the live check, the finding resolved 3 milliseconds after the press. A longer scan gets "The result follows
on this page.", and the automatic refresh shows its result. A user can think that a form with a wait of more than 5 seconds has a fault.
In Settings, the answer names the Findings page, because the Settings page has no findings and no automatic
refresh (repair 2).

**DECISION w056-5: all users see the last scan, and only an administrator can start a scan.** The card states "All
users see when syncwatch last checked". Viewers and open access see the time but no button. The dashboard refuses
their request (403). Without a login, it shows the login page (303). No scan starts.

**DECISION w056-6: no settings notice for "Scan now".** A scan changes no setting and only reads. The INFO log line
records each scan that an administrator starts.

**DECISION w056-7: "Scan now" also on S1 and S2.** The task asks for the button on each structure finding (S1 to S7).
syncwatch reads S1 and S2 from the folder paths of Syncthing, and the next full check or event updates them. On these
findings the button scans the shares of the server. This is correct, but it does not change S1 or S2.

## (b) Helper folders in the example settings of the studio

**Before.** Helper folders next to the project folders, for example `_archive` and `_templates`, got S4 (Incorrect
name). The same helper name in 2 shares also got S6. On realsim, a new `_archive` in AKKA-LIVE-4FINALS got S4.

**Changed.** `examples/ivar.yaml` adds `'_*'` to `structure.ignore_dirs`, with this comment:

```yaml
  # The pattern '_*' is for the helper folders next to the project folders,
  # for example _archive, _templates and _libraries. syncwatch skips each
  # directory whose name starts with "_". Such a directory gets no structure
  # finding (S4 to S7). syncwatch does not search it for nested project
  # folders (S3), also inside a project folder.
  ignore_dirs: ['@Recycle', '@Recently-Snapshot', '.streams', '.@__thumb', '@eaDir', '.stversions', '.stfolder', '.*', '#recycle', '_*']
```

What `ignore_dirs` skips, from the code:

- A top-level directory of a share with such a name gets none of S4 to S7 (`rules.directories`).
- The scans do not list the contents of such a directory, at the top of a share and inside a project folder (`scan`,
  `rescanFolders`, `descend`).
- A path through such a directory is never a nested project folder (`nestedIn`, `events.go`). This rule applies to the
  scan, the events and the entries that syncwatch keeps between scans.

`config.DefaultIgnoreDirs` does not change. The card asks for a list in the example settings of the studio, not for a
new default for each team. The kit reads the `structure:` block of this file for its bootstrap files. Thus a slot
with a build of this branch skips helper folders.

**Tests.** Both tests read `examples/ivar.yaml`, and both fail without `'_*'`.

- `internal/rules/example_test.go`, `TestStudioExampleSkipsHelperFolders`:
  - The example parses.
  - `_archive` in 2 shares, `_templates` and `_libraries` get no finding.
  - A new project folder that is not in Syncthing still gets S7.
  - With the default `ignore_dirs`, the same folders get S4, and `_archive` also gets S6.
  - `'_*'` is not in `DefaultIgnoreDirs`.
- `internal/collector/example_test.go`, `TestStudioExampleNestedScanSkipsHelperFolders`: the nested scan does not list
  `_old` inside a project folder. It finds the project folder below `renders`, and `nestedIn` agrees.

- **Repair 1. A share that the scan cannot list.** Before, the scan moved the last scan of the server also when the
  listing of a share failed. Each stale finding of the share then showed "last scan <now>", and the answer was
  "complete". Now each share has `ListedAt`, the end of its last listing. A finding of the share shows that time and the
  error. `LastStructureScan` and the API value move only for a scan that listed at least 1 share, or that found no
  share. The answer names each share that the scan cannot list, in red. The log line `structure scan done` has
  `share_errors`.
- **Repair 2. The answer in Settings.** Before, Scan now in Settings answered "The result follows on this page." or "The
  result is on this page.". The Settings page has no findings. Now the answer names the Findings page there.
- **Repair 3. A scan that stops before the end.** Before, a scan whose session ended counted as a scan. The answer
  promised a result, and the dashboard refused the next press for 30 seconds. Now `ScanStart.End` tells how the scan
  ended. A stopped scan does not count for the timed scans and for the 30 seconds. The answer is red and does not wait
  for an evaluation. A stopped baseline scan still counts for the next baseline scan. Thus sessions that end during a
  long baseline scan do not start it again and again. This is the same as before W-056.
- **Repair 4. The Overview tile.** Before, the tile showed the start of the last scan, and the finding showed its end. Now
  the tile shows `LastStructureScan` with the same format as the finding.
- **Repair 5. A test for the connection of Scan now to the collectors.** `TestScanNowReachesTheCollector` runs `Run`
  against a fake Syncthing, in password mode and in proxy mode. Without the line `ScanNow: mgr.ScanNow`, both parts
  fail. With `login=password` in proxy mode, the proxy part fails.

## Notes for the integrator

- In the kit, the log line has the address of the edge container (`ip=10.129.1.100`), because the edge forwards the
  host ports. A real installation logs the address of the browser, or of the proxy, the same as the other log lines.
- This is not of this branch: a finding that is less than 2 minutes old shows "open 1 seconds". `rules.Ago` writes
  "%d seconds" also for 1 second. STYLE.md (decision 18) asks for "1 second".
- This is not of this branch: with the gate, syncwatch sees a share that is not mounted as an empty share. The listing
  of the share is empty. Then `exists` lists the parent (`/share/`), but the gate refuses it ("directory not in a
  permitted browse root"). `exists` keeps the share when the listing fails. Thus the share has no error, and its S4 to
  S7 findings resolve. The live check of the repairs saw this on s29 with the gates
  (`live\live-a0-moved-share-looks-empty.json`, `live\gate-browse-parent.txt`). Without the gates, the share gets the
  error "not found on the server". The studio uses the gates.

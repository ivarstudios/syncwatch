## Contract differences

1. Names of the stage: branch `sim/r2-0`, worktree `the test kit`, changes file `docs/changes/r2-0.md`
   (the plan: `sim/r2-f`, `wt-r2-f`, `r2-f.md`). The evidence directory is the plan's `the test kit`.
2. Templates: 2 defines in `settings_api.html`, `settings-api` (the `#api` card) and `settings-api-new-token` (the "New API
   token" panel), not 1. The panel is at the top of the page and the card further down: 1 define at the place of the card
   moves the panel down, and the page HTML is no longer the same: the token that shows only once is then below the
   fold. Both are in fixer 5's file; `settings.html` (fixer 1) only includes them.
3. `servers[].site` message: `Server <ID>: the site (servers[].site) …` with the server ID, as every other server message
   of `Validate` (the plan's example says "Server SOL").
4. Names added to the contracts: `store.LegacyTokenName = "API token"` (the name of the migrated token; for the import rule
   of fixers 1, 5 and 8). Unexported: `config.siteOK`, `config.canonicalWebhook`, `store.decrypt`, `store.newTokenID`,
   `web.hasAPIToken`, `web.dropAPITokens`, the limits of `AddProgress`.
5. `ReplaceAPIToken(id, token, at)` sets `created_at` to `at` (the time of the new value; the contract does not say what
   `at` is for). Thus a replaced token moves to the end of the list "oldest first".
6. `TouchAPIToken`, `ReplaceAPIToken` and `DeleteAPIToken` answer `ErrNoToken` for an unknown ID. `AddAPIToken` and
   `ReplaceAPIToken` refuse an empty value (a plain error). `AddAPIToken` trims the name and also refuses control and format
   characters (`ErrTokenName`); the limit is checked before the name.
7. `AddGap` keeps the gaps that ended in the 30 days before the end of the newest gap, not before the clock: the same in
   use (the gap of a start ends now) and the same in tests at each date.
8. `MarkRepeated` marks only the records that are open in the engine. `mark` (PingedAt) also writes a resolved record;
   `MarkRepeated` does not (C2: "of open records").
9. The 2 "(behaviour)" items of F9 (the API token) are wider than "same behaviour" (see F9): Replace and Revoke also
   delete the rows of `api_tokens`, and `HasToken` also counts the rows. And `handleServerSave` keeps the site.
10. JSON and YAML tags: `site`, `servers[].site` and `devices` are `omitempty` in YAML and JSON, `repeat_urgent` also in
    JSON. A configuration that does not use them is stored and exported as before.
11. `ChangedSections` puts "Devices" after "Servers" (the plan does not give the place; fixer 1 can move it to the place
    of the card).
12. Site rule: also refuses text that is not valid UTF-8 (part of "no control characters").

## Decisions

- DECISION: the ERROR and WARNING counts of a server card count the open findings (not snoozed or ignored) whose server
  is this server or whose related servers contain it: the per-server rule of `/api/v1/ha` (C7). Thus H2 "Servers AKKA
  and SOL are not connected" (server akka, related sol) shows on both cards. The Overview tile counts only the findings
  whose server is this server.
- DECISION: `hx-trigger="every 60s, sse:update"` instead of the plan's `sse:update` alone. The engine sends an update
  only when something visible changes; a screen that stays open at night would keep "open 3 minutes", a "from 08:12" of
  yesterday and an old notification line for hours. The order of the 2 triggers keeps the word `sse:update` alone in the
  attribute: `app.js` finds the live sections with `[hx-trigger~='sse:update']` after a lost connection. Easy to revert
  (one attribute).
- DECISION: times on the lobby are the clock time when they are today in the configured zone ("from 08:12", "last
  change 18:42"), else the date and the time ("from 2026-10-10 21:04"). C11 shows only the clock time; a page that stays
  open for days needs the date. No "today" (the r1 rule of W-004).
- DECISION: `?theme=light` in addition to the plan's `?theme=dark`: a screen whose browser prefers dark can show the
  light colors. Other values are ignored.
- DECISION: the lobby shows the notification failure as one line without the error text and without a link. Every
  page shows the failure (r1); on a screen it tells everybody that urgent messages do not reach Discord.
- DECISION: a finding message in the list is cut after 160 characters with "…" (the Findings page has the complete
  message), thus a list of 10 findings fits better on a screen. A complete device ID in a message is shortened to
  `model.ShortID(id) + "…"` (C12) before the cut. The rules write no device ID in a message; the name that a device sends
  can be any text.
- DECISION: "PCs connected now" counts the PCs (not the devices of polled or disabled servers) that are connected to a
  server of the group that is up. When a server of the group is not up and loaded, the count is "N or more", or
  "unknown" when N is 0. A group of only disabled servers has no PCs line. In the kit each NAS knows every PC, thus both
  sites show 6 while the VPN works.
- DECISION: the choice between site rows and server rows counts the distinct sites of the enabled servers (fixer 2 puts
  no disabled server into `SiteLinks`).
- DECISION: the cards show no connection error of the server (the H1 finding in the list has it) and no "Open in
  Syncthing" link, also for an administrator: the lobby is the same page for each role.
- DECISION: the lobby uses no `data-site` attribute: fixer 6's site filter in `app.js` hides the elements with a
  `data-site` of another site (localStorage `sw-site`), and the lobby includes `app.js`. The lobby has its own filter
  (`?site=`), on the server.

## README lines (for the Docs stage)

A new section after "Notifications" (or before "JSON status API"), in STE (checked: `ste-mapping.md` DOC-7001..7019):

```markdown
## Lobby page

The lobby page `/lobby` is a read-only full-screen view for a screen in the office. It shows the health line, the
connections between the sites, the servers of each site and the open urgent and ERROR findings.

- Each server shows its state, its folders and the number of open ERROR and WARNING findings.
- Each site shows the number of PCs that are connected to its servers now.
- The list shows at most 10 urgent and ERROR findings, without details. The page has no links, no forms and no device IDs.
- The page refreshes automatically, as the other pages do.
- `/lobby?site=Branch%20office` shows only the servers, the connections and the findings of one site. Type the name of
  the site exactly as the configuration has it, with the same capital letters.
- `/lobby?theme=dark` always shows the dark colors, and `/lobby?theme=light` always shows the light colors. Without this
  option, the page uses the color setting of the browser.

To show the lobby page on a screen:

1. In Settings → Access, set the viewer access. With "open, without login", the screen needs no login. With "with the
   viewer password", type the viewer password on the screen one time.
2. For a screen that stays logged in, set `access.session_ttl` to a long time, for example `365d` (the maximum).
3. Open `https://<host>/lobby` in the browser of the screen, in full-screen mode.

The lobby page needs no API token. When the login ends, the screen shows the login page. After the next login, the
screen shows the same lobby page again.
```

For "What you must do after the update" (with fixer 8's W-027): over HTTPS each session from before the update ends; a
lobby screen with the viewer password needs one login after the update.
